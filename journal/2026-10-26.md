## Topics

1. 目標是做一個適合 iPad 的 Excalidraw fork：Apple Pencil（壓力、傾斜）、簡易動畫編輯與播放、iPad 與桌面同步（上課時用 iPad 當白板，筆電螢幕分享）、以及分頁／投影片。
2. 工作方式只走分支，不直接改 main。這個 repo 的預設分支是 `master`。`ipad-features` 從已經合併 GitHub Pages 部署的 `master` 拉出。PoC 分支使用 `poc/` 前綴。`poc/` 目錄放獨立小專案（例如單獨的動畫編輯器），證明可行之後才考慮合回主線。
3. 用 OpenSpec 為每個變更維護正式規格。
4. GitHub Actions 用輕量範本：推送到 `poc/**` 分支時跑 PoC 測試；主線變更時重新部署 Pages。
5. 角色寫成 Claude Code 風格的 Markdown，放在 `.claude/agents/`：architect、implementer、tester、recorder。
6. 目錄分工：`docs/` 放討論備忘，`journal/` 放有日期的開發日記，`openspec/` 放規格，`poc/` 放概念驗證，`.claude/` 放 agents，以及以後的 commands、skills、hooks。
7. 現在不開始寫功能。架構要先通過。

## Decisions

- 不直接在 `master` 上開發。整合用分支與 PR。
- `ipad-features` 是這次環境分支，起點是已合併 Pages 部署 workflow 的 `master`（PR #1）。
- PoC 是獨立小專案，各自依賴，不進根目錄 Yarn workspaces。分支名為 `poc/<name>`。
- 每個正式變更用 OpenSpec 記錄在 `openspec/`。
- Actions 範本只讓 PoC 測試工作生效。Pages 重新部署維持由既有的 `Deploy GitHub Pages` 在 `master` 上執行；範本裡對應的觸發保持停用，避免同一次推送排出第二個正式部署。
- 四個角色固定為 architect（架構）、implementer（實作）、tester（驗證與開 issue）、recorder（OpenSpec）。
- 根目錄原本沒有 `docs/`。上游文件在 `dev-docs/`，維持不動。這個 fork 的討論備忘放在新建的 `docs/`。
- 不開始寫功能程式。Apple Pencil、動畫、同步、投影片的架構要先同意。

## File storage

檔案儲存用兩層。

- Tier 1：檔案放在瀏覽器／PWA 的本地儲存（IndexedDB 或 localStorage），編輯時先求快。
- Tier 2：使用者以 Google 帳號登入後，可以透過 Google Drive API 把檔案直接存到 Google Drive，讓 iPad 與桌面都能讀到同一份。
- 以 email 或 zip 匯出是可選的加分項，不是必要功能。
- 在 iPad 上可以用 Web Share API，把打包好的檔案分享到 Google Drive 或其他 app。
